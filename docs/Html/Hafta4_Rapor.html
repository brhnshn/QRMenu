4. Transaction Yönetimi & Concurrency Kontrolü

🔄 Atomik Transaction

  • Sepet → Sipariş dönüşümü tek transaction içinde
  • SepetDetay → SiparisDetay kopyalama
  • Sepet temizleme (ürünler + toplam sıfırlama)
  • Hata durumunda otomatik rollback

🛡️ Concurrency (RowVersion)

  • Sipariş entity'sinde byte[] RowVersion
  • EF Core [Timestamp] ile otomatik kontrol
  • DbUpdateConcurrencyException yakalama
  • Kullanıcıya "sayfa yenile" mesajı

4.1 Provider-Aware Transaction Stratejisi

Sorun: InMemory database provider'ı transaction desteklemiyor.
Çözüm: ProviderName kontrolü ile runtime'da provider tespiti. PostgreSQL (Npgsql) için ExecutionStrategy + BeginTransactionAsync kullanılırken, InMemory testlerde transaction atlanıyor. Bu şekilde aynı servis kodu hem production hem test ortamında sorunsuz çalışıyor. 
var supportsTransactions = _context.Database.ProviderName
    != "Microsoft.EntityFrameworkCore.InMemory";

if (supportsTransactions)
{
    var strategy = _context.Database.CreateExecutionStrategy();
    return await strategy.ExecuteAsync(
        () => ExecuteSiparisOlusturAsync(sepetId, notlar, true));
}
return await ExecuteSiparisOlusturAsync(sepetId, notlar, false);

// Sipariş satırına tıklandığında stepper'ı güncelle
function highlightProgress(row) {
    const durum = row.dataset.durum;
    const stepMap = {
        'Onaylandı': 1, 'Hazırlanıyor': 2,
        'Hazır': 3, 'TeslimEdildi': 4,
        'TamÖdendi': 5, 'KısmiÖdendi': 5
    };
    const step = stepMap[durum] || 0;
    // Tüm stepper-item'lara completed/active/cancelled class'ı ata
    document.querySelectorAll('.stepper-item').forEach((el, i) => {
        el.classList.toggle('completed', i + 1 < step);
        el.classList.toggle('active', i + 1 === step);
        el.classList.toggle('cancelled', durum === 'İptal');
    });
}

// Web Audio API — programatik bildirim sesi (harici dosya gereksiz)
function bildirimSesiCal() {
    const ctx = new (window.AudioContext || window.webkitAudioContext)();
    const osc = ctx.createOscillator();
    const gain = ctx.createGain();
    osc.connect(gain);
    gain.connect(ctx.destination);
    osc.type = 'sine';
    osc.frequency.setValueAtTime(830, ctx.currentTime);
    osc.frequency.setValueAtTime(1100, ctx.currentTime + 0.1);
    gain.gain.setValueAtTime(0.3, ctx.currentTime);
    gain.gain.exponentialRampToValueAtTime(0.01, ctx.currentTime + 0.5);
    osc.start(ctx.currentTime);
    osc.stop(ctx.currentTime + 0.5);
}
Web Audio API Avantajları:
  • Harici ses dosyası gereksiz — tamamen programatik üretim (830Hz → 1100Hz sine wave)
  • Base64 audio sorunları ortadan kalktı (mobilde oynatma engeli, dosya boyutu)
  • Ses süresi: 0.5 saniye, exponential decay ile doğal "ding" efekti

10. Middleware Düzeltmeleri

10.1 AJAX-Aware 401 JSON Yanıtı

Hata: AJAX ile sipariş gönderildiğinde "Microsoft.EntityFrameworkCore..." is not valid JSON hatası alınıyordu.
Neden: TokenValidationMiddleware 401 yanıtında düz metin döndürüyordu. JavaScript res.json() parse edemiyordu.
Çözüm: WriteUnauthorized() helper metodu: AJAX isteklerini (Content-Type/Accept/X-Requested-With) tespit edip {"success":false,"message":"..."} JSON döndürür. Normal tarayıcı isteklerinde düz metin döner. 
private static async Task WriteUnauthorized(HttpContext ctx, string msg)
{
    var isAjax = ctx.Request.Headers["Content-Type"]
        .ToString().Contains("application/json")
        || ctx.Request.Headers["Accept"].ToString().Contains("application/json")
        || ctx.Request.Headers["X-Requested-With"] == "XMLHttpRequest";

    ctx.Response.StatusCode = 401;
    if (isAjax) {
        ctx.Response.ContentType = "application/json";
        await ctx.Response.WriteAsync(
            $"{\"success\":false,\"message\":\"{msg}\"}");
    } else {
        await ctx.Response.WriteAsync(msg);
    }
}

18.8 Sipariş Saati UTC Fix (v1 → v2)

Sorun (v1 — 10 Mart): Sipariş oluşturma saati DB'de DateTime.UtcNow ile kaydediliyor (doğru). Ancak JSON endpoint'lerde .ToLocalTime() çağrılmadığı için fiş ve tabloda saat 3 saat geri yazılıyordu (UTC+0 yerine UTC+3 Türkiye).
İlk Çözüm (v1): .ToLocalTime() eklendi — localhost'ta çalışıyor çünkü makine TZ = Europe/Istanbul.

Sorun (v2 — 11 Mart): .ToLocalTime() sunucu makinesinin zaman dilimine bağlı. Canlıda (VDS/Docker) sunucu UTC saat dilimindeyse yine 3 saat geri gösterilir. Nitekim deploy sonrası admin panelde sipariş listesi 09:54, fiş 12:54 gösterdi → Razor tarafı hâlâ .ToLocalTime() kullanıyordu.
Etkilenen Noktalar:
  • AdminController → /admin/siparis-detay/{id} (fiş tarihi)
  • AdminController → /admin/siparisler-json (tablo tarihi)
  • SiparisController → /siparis/{id} (müşteri detayı)
  • SiparisController → /siparis/siparislerim (müşteri listesi)
  • Siparisler.cshtml → Razor view'daki sipariş tarihi kolonu
Kesin Çözüm (v2): .ToLocalTime() tamamen kaldırıldı. Yerine açık saat dilimi dönüşümü getirildi: 
private static readonly TimeZoneInfo _turkeyTz =
    TimeZoneInfo.FindSystemTimeZoneById(
        OperatingSystem.IsWindows()
            ? "Turkey Standard Time"
            : "Europe/Istanbul");

private static string ToTurkeyTime(DateTime utc) =>
    TimeZoneInfo.ConvertTimeFromUtc(
        DateTime.SpecifyKind(utc, DateTimeKind.Utc), _turkeyTz)
        .ToString("dd.MM.yyyy HH:mm");
Böylece sunucu hangi TZ'de olursa olsun (UTC, CET, vb.) her zaman Türkiye saati gösterilir. OperatingSystem.IsWindows() ile Windows/Linux farkı da ele alındı.
