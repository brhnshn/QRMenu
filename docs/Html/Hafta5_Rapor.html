3. Personel Giriş Sistemi — Cookie Authentication

3.1 AuthController Akış Özeti

Tüm personel panelleri (Garson, Mutfak, Kasa, Admin) erişim için kimlik doğrulaması gerektirir. Giriş yapıldığında kullanıcının KullaniciRol enum değerine göre otomatik olarak ilgili panele yönlendirilir. 
private IActionResult RedirectToRole(string? role)
{
    return role switch
    {
        "Admin"  => RedirectToAction("Index",   "Admin"),     // → /Admin
        "Garson" => RedirectToAction("Masalar", "Garson"),    // → /Garson/Masalar
        "Kasa"   => RedirectToAction("Masalar", "Kasa"),      // → /Kasa/Masalar
        "Mutfak" => RedirectToAction("Panel",   "Mutfak"),    // → /Mutfak/Panel
        _        => RedirectToAction("Login")
    };
}

3.2 Yetkilendirme (Authorization) Yapılandırması

Controller Authorize Attribute Erişebilen Roller
GarsonController [Authorize(Roles = "Admin,Garson,Kasa,Mutfak")] Tüm personel
MutfakController [Authorize(Roles = "Admin, Mutfak")] Admin + Mutfak
KasaController [Authorize(Roles = "Admin, Kasa")] Admin + Kasa
AuthController — Anonim (Herkese açık) — Tüm kullanıcılar

3.3 Login UI Tasarımı

🎨 Görsel Tasarım

  • Gradyan arka plan (linear-gradient(135deg, #f3f4f6, #e2e8f0))
  • Ortalanmış kart yapısı (.login-card)
  • Yuvarlatılmış köşeler (border-radius: 16px)
  • Gölge efekti (box-shadow: 0 10px 40px)
  • Responsive — mobil ve masaüstü uyumlu

🔐 Güvenlik Özellikleri

  • Cookie Authentication Scheme ile güvenli oturum
  • Zaten giriş yapmışsa tekrar login sayfasını gösterme
  • Claims: NameIdentifier, Name, Role, FullName
  • Logout ile güvenli çıkış ve cookie temizleme
  • Hatalı giriş mesajı (ViewBag.Error)

5. Mutfak Paneli (KDS — Kitchen Display System)

5.1 MutfakController Endpoint'leri (2 adet)

HTTP Route Açıklama
GET /Mutfak/Panel Son 24 saat içindeki bekleyen siparişleri (Onaylandı/Hazırlanıyor) kart olarak listeler.
POST /Mutfak/DurumGuncelle/{siparisId} Siparişi "Hazırlanıyor" veya "Hazır" durumuna çeker. Hazır ise garson'a bildirim gönderir.

5.2 KDS UI Özellikleri

⏱️ Bekleme Timer

  • Her sipariş kartında dinamik süre sayacı
  • 5 dakika+ → Sarı border
  • 8 dakika+ → Kırmızı border
  • Sıralı aksiyon: Önce "Hazırlanıyor", Sonra "Hazır"

📡 SignalR Bildirim Akışı

  • Yeni sipariş gelince KDS otomatik yenilenir
  • "Hazır" dendiğinde Garson'a özel SiparisHazir eventi
  • Garson ekranında tam ekran overlay + sesli uyarı
  • Bildirim el ile kapatılana kadar kalır (reload'u engeller)

5.3 SignalR Hazır Bildirimi Kod Akışı

// MutfakController — DurumGuncelle metodu
if (durum == SiparisDurum.Hazir)
{
    var sip = await _context.Siparisler.Include(s => s.Masa)
                   .FirstOrDefaultAsync(s => s.Id == siparisId);
    if (sip != null)
    {
        // Önce "SiparisHazir" (overlay gösterir)
        await _menuHub.Clients.All.SendAsync("SiparisHazir", sip.Masa.MasaNo);
    }
}
// En son "SiparisGuncellendi" (reload, bildirim açıkken ertelenir)
await _menuHub.Clients.All.SendAsync("SiparisGuncellendi");

7. AuditLog — EF Core Interceptor ile Otomatik İzleme

7.1 Çalışma Prensibi

Mekanizma: SaveChangesInterceptor sınıfını genişleten AuditLogInterceptor, her SaveChanges / SaveChangesAsync çağrısından önce tetiklenir. Değişen entity'lerin eski ve yeni değerlerini JSON formatında AuditLoglar tablosuna yazar.

7.2 İzlenen Tablolar

Tablo Adı İzlenen İşlemler Örnek Senaryo
Siparis INSERT, UPDATE, DELETE Sipariş durumunun Onaylandı → Hazırlanıyor değişimini loglar
SiparisDetay INSERT, UPDATE, DELETE Ürün iptali veya ödeme durumu değişikliğini takip
Urun INSERT, UPDATE, DELETE Fiyat değişikliğinin eski ve yeni değerini saklar
Masa INSERT, UPDATE, DELETE Masa aktiflik durumu değişikliğini izler
Kullanici INSERT, UPDATE, DELETE Personel rolü veya şifre değişikliğini loglar

7.3 AuditLog Kayıt Formatı

// AuditLog entity — veritabanına yazılan kayıt
{
    "Id":          42,
    "TabloAdi":    "Urun",
    "KayitId":     15,
    "Islem":       "MODIFIED",
    "KullaniciId": 3,
    "EskiDeger":   "{\"Ad\":\"Espresso\", \"Fiyat\":45.00}",
    "YeniDeger":   "{\"Ad\":\"Espresso\", \"Fiyat\":55.00}",
    "IslemTarihi": "2026-03-17T19:30:00Z"
}

8. Karşılaşılan Hatalar ve Çözümleri

Hata Kategori Çözüm
signalR is not defined (Panel, Garson, Kasa) Frontend / Script Sırası SignalR CDN referansı _AdminLayout.cshtml'de global olarak en üste yerleştirildi. Hatalı nested @section Scripts yapıları temizlendi.
Mutfaktan "Hazır" bildirimi 1 saniye görünüp kapanıyor SignalR / UX Önce SiparisHazir sonra SiparisGuncellendi olarak sıralandı. JS tarafında overlay açıkken reload engellendi (setTimeout + overlay kontrolü).
Kasa masalarında "Bakiye Bekleniyor" asılı kalıyor Backend / Sorgu SiparisDurum.Iade kontrolü bakiye filtrelerinde (AnyAsync) eksikti. İade durumundaki siparişler filtreye eklenerek boş masalar doğru gösterildi.
Garson "Teslim Et" butonu çalışmıyor Frontend / API Butonun onclick handler'ı doğru endpoint'e (/Garson/DurumGuncelle) ve doğru body yapısına ({ YeniDurum: "TeslimEdildi" }) bağlandı.
Sipariş mutfağa sayfayı yenilemeden gelmiyor SignalR / Hub SiparisEklendi eventi mutfak panelinde dinlenmeye alındı. JS client'ta connection.on("SiparisEklendi", ...) ile otomatik reload eklendi.
AuditLog: "MODIFIED" vs. "MODİFİED" (Türkçe İ) Testing / Kültür ToUpper() Türk kültüründe "I" → "İ" yapıyordu. ToUpperInvariant() ile kültür bağımsız hale getirildi.
Kasa ödeme tipi parametresi: "Kredi Kartı" vs "Kart" Frontend / Backend Uyumu Kasa/Odeme.cshtml'deki onclick fonksiyonuna gönderilen parametre "Kredi Kartı"'ndan "Kart"'a çevrildi — OdemeTipi enum ile eşleştirildi.
GitHub Actions build hatası: CS0234 missing namespace CI/CD / Git İlk push src/QRMenu.Web klasöründen yapılmıştı. Core ve Data projelerindeki yeni dosyalar (Interfaces, Interceptors) dışarda kalmıştı. Proje kök dizininden git add . ile tüm dosyalar eklendi.
